# Reproducing pilot C's tables and figures

Everything below runs from this branch (`pilot/c-bottleneck`). The GPU notebooks run on Kaggle (4×L4) inside the
competition's official starter environment. Every committed number can be recomputed on CPU from the committed result
files (`results/`), without a GPU. The competition data (tasks, snapshots, patches, traces) is never in this repository.
You need Kaggle access to the competition `gemma-4-developer-agent` to rerun any notebook.

## 0. Two ways to reproduce

1. **Recompute from the committed results (CPU, minutes).** Every table and figure comes from a JSON file in
   `results/` through a script in `pilot_c/`. See §2.
2. **Rerun the experiments (Kaggle).** Run the notebooks in §1 in order, download each notebook's output file, put it in
   `results/`, then run §2.

Environment for §2 and §4: Python ≥ 3.11 with `numpy`, `scipy`, `matplotlib` (any recent versions). Run from the
repository root:

```bash
pip install numpy scipy matplotlib pytest
```

## 1. Notebooks (run on Kaggle, in this order)

All notebooks are generated by `notebooks/build_notebooks.py`. Run them the same way (also in `notebooks/README.md`):

1. Open the official starter, https://www.kaggle.com/code/ryanholbrook/getting-started-gemma-4-developer-agent, and click
   **Copy & Edit**. This keeps its pinned environment (Python 3.12) and its inputs.
2. **File → Import Notebook**, then upload the `.ipynb` from `notebooks/`.
3. **Settings:**
   - Environment = **Pin to original environment**;
   - Accelerator = as in the table below (the GPU L4 x4 option appears only after the competition is attached);
   - Internet = **Off**.
4. Attach the earlier notebook's output named in the table (**Add input → Your Work → Notebooks**).
5. **Save Version → Save & Run All.** The first cell stops at once on any Python other than 3.12.

## 3. The benchmark audit (CPU; needs the competition data locally)

- Gold and no-patch verification of all 129 tasks: `notebooks/C00_gold_check__CPU.ipynb`.
- Import check for the src-layout repos (does the test run import the repo's code or the host's installed copy?):

  ```bash
  python -m pilot_c.audit_imports results/C00_audit_imports.json <task ids>
  ```

  Run it in the starter's Python 3.12 environment with the wheelhouse installed, and with the competition data at
  `/kaggle/input/competitions/gemma-4-developer-agent`. It runs each task twice, first as the harness does and then with
  the repo's `src/` first on the import path, each with the gold patch and with no patch.
- `results/C00_audit.md` combines both.

## 5. Checks run before every hand-off (CPU)

- **Unit tests:**

  ```bash
  pytest tests/test_stats.py tests/test_analyze_c04.py tests/test_analyze_c06.py tests/test_analyze_c03v.py tests/test_runtime_probes.py tests/test_probe.py tests/test_locate.py
  ```

  The analysis tests run on synthetic data built around the committed results. `tests/test_template_scoring.py` and
  `tests/test_server_shutdown.py` need local model tokenizer files or the harness wheels.
- **Notebook dry runs** with papermill (the executor Kaggle uses), under Python 3.12 with the real wheelhouse and a mock
  model server:

  ```bash
  WHEELHOUSE=<dir with the 41 wheels> tests/papermill_dryrun.sh <local competition dir> <py3.12 venv> <out dir> C00 C01 C03 C04 C05 C06 C03v
  ```

  Freeze tests: keys `C01F C03F C04F C05F`.
